## Entry 3

**UT time:** 2026-09-11T00:54:16Z

**Prompt:** Are you using proper coordinates and elevation for Keck?

**Model:** Sonnet 5

**Tokens/CO2:** see `Logs/log_summary.csv` (authoritative, written by the Stop hook)

**Narrative:**

A direct fact-check request on the `KECK = EarthLocation(...)` constant
hardcoded in both `scripts/keck_2026oct02_calculations.py` and
`scripts/build_keck_night_plan.py` (lat 19.8263°N, lon -155.4783°W, height
4160 m — in place since the Keck scripts were first written on 2026-09-09).
Rather than trust a quick web search (which turned up several slightly
different values across Wikipedia, GPS-lookup sites, etc.), checked against
astropy's canonical site database directly:
`astropy.coordinates.EarthLocation.of_site('keck')`, sourced from the IRAF
Observatory Database.

Result: longitude (-155.4783°) and elevation (4160 m) were already exactly
right. Latitude was wrong — 19.8263° vs. the correct 19.828333°, an error of
~7 arcsec (~220 m on the ground). Fixed both files, adding a comment citing
the verification source so it can't silently drift back. Reran the full
pipeline to check impact: identical twilight times, the same 5 selected
targets, airmass values shifted only in the 4th-5th decimal place — the
error was too small to matter for this particular run, but not a reason to
leave a wrong constant in place. Added Prompt 11 to
`KECK_LRIS_2026OCT02_SUMMARY.md` (including the Ephemeris table's latitude
value), one new Lesson Learned (verify hardcoded site constants against a
canonical source, not a web search alone), and updated `claudes_brain.md`
(v0.24, plus a new quick-reference "Keck Observatory coordinates" note for
future sessions).
