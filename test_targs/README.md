## Seasons

A plan is mostly decided by which RAs are up, so each seasonal table clusters on the RA transiting near local midnight. Running one against the wrong date should reject nearly everything -- that is a test, not a bug.

| table | RA centre | run month |
|-------|-----------|-----------|
| `autumn_ffffpz.csv` | 1h | October |
| `winter_ffffpz.csv` | 7h | January |
| `spring_ffffpz.csv` | 13h | April |
| `summer_ffffpz.csv` | 19h | July |

## The three that must fail

Silently guessing is the dangerous outcome, so these exist to prove the planner refuses rather than guesses. If a release reads any of them without complaint, that release is broken.

- `bad_ambiguous_ra_units.csv` -- a bare numeric `ra` whose values are all <= 24 is either hours or degrees, and the two differ by a factor of 15.
- `bad_burst_position_only.csv` -- `FRB_RA`/`FRB_Dec` is where the burst was, not where the host is. Pointing there observes blank sky.
- `bad_odd_headers.csv` -- journal-style headers that no alias covers; the column-mapping path should be offered instead.

## Example

```bash
night-planner calc --instrument kast \
    --targets-csv test_targs/autumn_ffffpz.csv \
    --output-dir Night_plans/SIM-Autumn-01 \
    --date 2026-10-20
```
